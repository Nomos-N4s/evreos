**Input**: Design documents from `/specs/001-evreos-v1/`

**Prerequisites**: `plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/README.md`,
`quickstart.md` — all merged to `main`.

**Tests**: Tests are requested. The founder's standing instruction is that everything is
adversarially reviewed and thoroughly tested, so every task that lands behaviour lands its tests
with it. There is no separate testing phase, because a testing phase is where tests go to be cut.

**Organization**: Tasks are grouped by user story so each story can be implemented, tested and
delivered independently.

- **[P]**: may run in parallel — different files, and nothing it depends on is incomplete
- **[Story]**: `[US1]`, `[US2]`, `[US3]`; absent in Setup, Foundational and Polish

## The ordering constraint that governs everything below

`research.md` establishes that the merged `Engine` trait **cannot be implemented on either
shipping backend**. `load` is synchronous while WebView2 is UI-thread-affine and wry's macOS
delegates are `MainThreadOnly`, so the only synchronous route is a nested message pump that
breaks SC-006 by construction. And `Result<Page, LoadError>` cannot express engine-initiated
navigation, in-flight state, or a title arriving on its own event.

**T011 revises the trait, and every platform backend is ordered behind it.** This is the second
implementation revealing what an assertion could not, which is the whole reason Principle III
requires one from day one.

## Dependencies

- **Phase 1 → Phase 2 → Phases 3, 4, 5 → Phase 6.**
- **T011 (the `Engine` trait revision) blocks every platform backend task in Phase 3.**
- **US2 and US3 both depend on US1's shell.** Neither is deliverable without a browser to host it.
- US2 and US3 are independent of each other and may proceed in parallel once US1 is complete.
- The four spikes (Q-E10, Q-E11, Q-E11b, Q-E12) each depend on that tier's pinned reference
  machine existing (T173), and each blocks the claim its answer would license — never the reverse.

## Implementation strategy

**MVP is Phase 3 alone.** User Story 1 signed out is a shippable private browser and the only
story that stands by itself; the constitution requires it to be genuinely good rather than a
degraded mode, so it is finished before the super-app work starts.

Deliver incrementally: Phases 1 and 2, then Phase 3 to a releasable browser, then US2 and US3 in
either order, with Phase 6's release-blocking items landing before any public build.

## Parallel opportunities

Tasks marked `[P]` within a phase touch disjoint files and depend on nothing incomplete. The
largest parallel groups are the per-requirement shell surfaces in Phase 3, the four spikes once
their runners exist, and the diagnostics components in Phase 6.
